// Project aim

To build out a multi brand Design system to help ATG tickets grow and scale their digital offering.


A full foundation of a design system was needed to move ATG foward and streamline the design team to get them all to use the new system.


The initial stages were to look into the fundamentals, component review, file structures in figma, organisation of workflows, governance and documentation. Following on from this a full UI library was built in Figma using all the latest features to unify the workflow of the designers, keeping file size small to make sure the system was fast and robust.


Design tokens were then introduced to firm up the multiple brand capabilities ATG were looking for. Once this was in place a GIT repository was built to handle the centralisation of the Design System so the teams could push and pull live code up to and down from the central servers. Using the GIT repos allows ATG to manage multiple designers across multiple branches to keep the velocity of work to a maximum.


I managed the new design tokens through GIT repository, Figma and Token Studio for Figma (3rd party plugin), this gave me a great GUI to set up and manage all our tokens and was much easier then just using Visual Studio but also allowed fellow designers with no code expereience to engage with the system.



Working very closely with the engineering team we were able to establish a pattern of working, best practice and for handover between design and finished components. We also worked in key touch points and automation into the process so everyone was involded and notified where needed. This communication trail was acheived by using slack workflows, figma branching, GIT branching to allow for accountablity and tracking to monitor the systems progression


The main KPI's for this project was to allow the simple theming by a sole designer across multiple modes (light/dark mode for AA compliance). Building a new brand could be built from a white label base theme in minutes, rather than days or weeks, so an incredible time saving was acheived. To have one central repository for the components used across ATG to give the stability, simplicity and to maintain a large digital estate with less effort. The tokens are also scalable and can be used across web (SASS), iOS (Swift) and Android (XML) through styledictionary transforms.


Tools used; Figma, GIT, Visual Studio, Axure, iOS - swift, MIRO, Notion.

// Project steps

  1. Set up the foundations for the design system
  2. Roll out a new UI library & Organised into sections (atomc design)
  3. Build out the design tokens to cover multi-brand light and dark modes
  4. Process & Governance
  5. Documentation
  6. Mentoring the design team

// Foundations

Foundations are the building blocks to a design system, so getting this part right and well thought out pays off down the line. So a new clean Figma structure was established getting feedback and input from all the team to align design language and awareness. Keeping files separate as we knew this would grow at an exponential rate, meaning that file size needed to be kept as small as possible.

// New UI Library

Following on from our foundations we started to set up a new component library following the atomic design structure. The library was build off the back of MUI design library so we could hit the ground running. At this stage we introduced the design tokens into the library

// Build out design tokens

We utilised design tokens early on in the foundations and components, so colour, space and typography. The impliemntation of the dark mode and the aility to theme from a base template was still to do. Working closely with the team especially engineering, we streamlined the token set multiple times to get a simple structure but also to improve the semantics of the typography tokens to make the design choices clearer and less ambiguous.

// Process & Governance

Process is a huge part of the design system and being able to track and maintain the standards but lso to keep things consistant. Simple hand over documents were established and reviewed every sprint to keep the evolution moving. On the design/Figma side the new Tokens plugin allows us to push changes to GIT branches to the team is able to work on multiple JIRA issues at once and track its journey through the sprint.

// Documentation

Another important strand to a deign system are the documents that support and inform the team on how to use or patterns that have been established, from accessability to character lengths, all imperitive when running a system at scale.

// Mentoring

Passing knowledge around the team and cross polinating what and how to use the system is just as important. The buy in from other teams brings great value to the system. Once more and more people are on board, real speed, agility and the ability to move at pace becomes very apparent.
